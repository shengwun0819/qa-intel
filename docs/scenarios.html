SETUP

第一次使用：從安裝到第一個指令

所有 skill 在沒有專案配置的情況下仍可運作（通用模式）。Step 2–3 是讓工具更貼合你公司的設定，非必要。

STEP 01
安裝 plugin
將 qa-intel clone 至 Claude Code plugin 目錄。
claude plugin install <repo-url>
STEP 02 選用
建立專案配置
複製 TestProject 為你公司的配置目錄。
cp -r projects/TestProject projects/MyCompany
STEP 03 選用
填入 project.md
設定 PM 工具、Bug 紀錄位置、裝置/範圍預設、自訂模板。不填則通用模式繼續。
STEP 04 選用
建立知識庫
掃描 repo，讓 risk-analyzer 與 gen-test-cases 有 codebase 背景知識。
/repo-scout
READY
開始使用
執行任意 skill。Phase 0 會自動偵測並載入你的專案配置。

GEN-TEST-CASES

產出手動測試案例

依你提供的輸入組合，skill 會自動調整分析深度。任何組合都能運作；輸入越多，案例越精準。

最簡情境：只有 Task ID
GEN
你有
ClickUp / Jira Task ID
指令
/gen-test-cases
讀取 Task 的 title、description、AC、留言。若有知識庫則自動補充 codebase 背景。輸出完整測試案例並寫入 PM 工具。
無 project.md 時以通用模式執行，裝置/範圍會在執行中詢問。

Task + PR URL
GEN
你有
Task ID GitHub PR URL

全組合（最完整）
GEN
你有
Task ID PR URL ai-plans 知識庫
指令
/gen-test-cases → 提供所有來源
同時取得 AC（Task）、變更範圍（PR diff）、設計意圖（ai-plans）、codebase 背景（知識庫）。產出的測試策略摘要會標注各資訊來源。
測試深度：執行時必選其一
DEVELOPMENT PHASE
受眾：RD｜目的：確認核心功能可用
  • Happy Path（1–3 條核心路徑）
  • 關鍵 Negative Cases（打壞主流程的情境）
  • Boundary Cases（留待 Verification 補）
  • 細節 Negative Cases（留待 Verification 補）
  • 文末附：Verification phase 待補清單
VERIFICATION PHASE
受眾：QA｜目的：完整覆蓋所有有意義情境
  • Happy Path（完整，含各種合法輸入組合）
  • Boundary Cases（數值/字串/時間/狀態邊界）
  • Negative Cases（缺欄位、格式錯誤、未授權、資源不存在…）
  • 已知 Bug 對應的迴歸驗證（若有 Bug 紀錄）
RISK-ANALYZER

PR / Branch 風險評估

不需要知識庫也能執行，但有知識庫時分析品質明顯更好。提供 ClickUp Task 則額外輸出 AC 覆蓋缺口分析。

Public PR（最簡入門）
RISK
你有
GitHub PR URL（public repo）
指令
/risk-analyzer → 貼入 PR URL
用 WebFetch 讀取 PR diff，分析 8 個風險維度。無需任何帳號設定。適合 Open Source PR review。
Private PR（需本機 repo）
RISK
你有
GitHub PR URL（private） Local repo path
指令
/risk-analyzer → PR URL + local path
改用 gh pr diff 讀取完整 diff。需要 gh CLI 已登入。
Branch（尚未開 PR）
RISK
你有
Branch 名稱 Local repo path
指令
/risk-analyzer → feat/xxx + local path
執行 git diff main...branch 分析。開發中即可提早評估風險，不用等 PR。
PR + ClickUp Task（最完整）
RISK
你有
PR URL 或 branch ClickUp Task ID
指令
/risk-analyzer → PR + Task ID
除 8 維度風險外，額外輸出 AC 覆蓋分析：哪條 AC 找不到對應實作、diff 有哪些不在 AC 裡的改動。
無知識庫（降級模式）
RISK
你有
PR URL 知識庫（尚未建立）
指令
/risk-analyzer → 選擇繼續
仍可執行，但無法對照「已知風險模組」做深度分析。Skill 會提示先執行 /repo-scout，詢問是否仍繼續。
直接貼入 Diff
RISK
你有
Raw diff 或變更說明
指令
/risk-analyzer → 直接貼上 diff
最靈活的入口，不需要 GitHub 帳號或 local repo。適合 code review 時快速臨時分析。
輸出內容（每次執行都包含）
🔴🟡🟢 風險明細表（8 個維度）
AC 覆蓋缺口分析（有 Task 時）
範圍外改動標記
建議測試重點清單
部署前 checklist
銜接 /gen-test-cases 的提示
REPO-SCOUT

建立 Codebase 知識庫

知識庫是快照，不上傳至 git，換公司或 repo 有大改動時重新執行。gen-test-cases 與 risk-analyzer 都會在背景自動讀取。

初次掃描（Comprehensive）
SCOUT
你有
Local repo path
指令
/repo-scout → path → comprehensive
掃描根目錄 + 核心 source 目錄，建立完整知識快照：架構、模組、API 清單、已知風險點。Token：20k–80k。
第一次加入新公司時建議執行，之後按需更新。
快速架構概覽（Quick）
SCOUT
你有
Local repo path
指令
/repo-scout → path → quick
只讀 README + package manager 檔案。快速了解 tech stack 與整體架構，不深入模組細節。Token：3k–8k。
定向掃描（Focused）
SCOUT
你有
Local repo path 目標模組或關鍵字
指令
/repo-scout → path → focused → keywords
只深入掃描與關鍵字相關的目錄與檔案。適合需要了解特定模組（例如「auth」、「payment」）時使用。Token：5k–15k。
Public GitHub Repo
SCOUT
你有
GitHub Repo URL（public）
指令
/repo-scout → GitHub URL
用 WebFetch 讀取 GitHub 上的檔案，不需要 clone。適合第三方 library 或 Open Source 專案分析。
Private repo 無法用 WebFetch，需 clone 至本機後提供 local path。
更新現有知識庫
SCOUT
你有
已有知識庫的 Local repo Major refactor 完成
指令
/repo-scout → 同 repo path → 覆蓋更新
重新掃描，更新 `knowledge/repos/.md`。知識庫會標注更新時間戳。日常小 PR 不需要更新，大架構調整後執行。
多個 Repo（微服務架構）
SCOUT
你有
多個 local repo paths
指令
/repo-scout（每個 repo 分別執行一次）
每個 repo 產出一份獨立的 `.md` 知識檔案。risk-analyzer 跨 repo 分析時，可同時讀取多份知識庫了解服務邊界。
在 project.md 的 repos 欄位列出 repo 名稱，可加速 skill 的自動匹配。
